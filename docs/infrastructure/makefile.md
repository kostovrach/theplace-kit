# Makefile

## Назначение

`Makefile` упрощает управление сборкой, деплоем и обслуживанием frontend-приложения на сервере.  
Содержит удобные команды для работы с pm2, сборкой Nuxt и логами.

Файл находится в корне проекта: `/srv/<название_проекта>/Makefile`

## Основные переменные

| Переменная     | Значение                       | Описание                                               |
| -------------- | ------------------------------ | ------------------------------------------------------ |
| `APP_NAME`     | `<название_проекта>-frontend`  | Имя процесса в PM2                                     |
| `APP_DIR`      | `/srv/<название_проекта>`      | Корневая директория проекта                            |
| `FRONTEND_DIR` | `$(APP_DIR)/frontend`          | Папка с Nuxt-приложением                               |
| `ICONS_DIR`    | `.../app/assets/svg/gen`       | Папка сгенерированных иконок (очищается перед сборкой) |
| `LOGS_DIR`     | `/srv/<название_проекта>/logs` | Директория с логами                                    |

## Доступные команды

| Команда            | Описание                                               | Когда использовать            |
| ------------------ | ------------------------------------------------------ | ----------------------------- |
| `make help`        | Показать список всех команд                            | Для справки                   |
| `make app-init`    | Первая инициализация (установка + сборка + запуск PM2) | При первичном деплое          |
| `make app-build`   | Установка зависимостей и сборка проекта                | Пересборка без деплоя         |
| `make app-clean`   | Удаление старой сборки (`.output`)                     | Перед новой сборкой           |
| `make app-deploy`  | Полный деплой (clean -> build -> reload)               | **Основная команда**          |
| `make app-reload`  | Graceful reload PM2 (без downtime)                     | После изменений               |
| `make app-restart` | Жёсткий рестарт PM2                                    | При критических изменениях    |
| `make app-logs`    | Открыть последний output.log в VS Code                 | Просмотр логов                |
| `make app-logtail` | Показать последние 100 строк логов в терминале         | Мониторинг в реальном времени |

## Примеры использования

```bash
# Первичная настройка проекта на сервере
make app-init
```

```bash
# Стандартный деплой после git pull
make app-deploy
```

```bash
# Только пересобрать проект
make app-build
```

```bash
# Перезапустить без пересборки
make app-reload
```

```bash
# Посмотреть логи
make app-logs
# или
make app-logtail
```

## Рекомендации

- Основной сценарий обновления приложения — `make app-deploy` (сразу после git pull)
- `app-reload` предпочтительнее `app-restart` в продакшене (минимальный downtime)
