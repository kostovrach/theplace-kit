# Theplace-kit <br> Управление фронтендом

Тут описан процесс сборки и деплоя frontend-части (Nuxt) на production-сервере с использованием **PM2** и основными сценариями в **Makefile**.

При условии, что проект размещается по стандартному пути:  
`/srv/<название_проекта>`

## Структура на сервере

```bash
/srv/<название_проекта>/
├── frontend/           # Nuxt-приложение
│   ├── .output/        # Сборка Nitro
│   ├── app/
│   └── ...
├── logs/               # Логи PM2
├── ecosystem.config.js
└── Makefile
```

## Конфигурация и основные команды

Файл `ecosystem.config.js` для управления pm2 лежит в корне проекта. Перед старом нужно заменить все плейсхолдеры (в нем и в Makefile) <название_проекта> на название проекта, обязательно эквивалентно названию репозитория. Также, при необходимости, нужно вручную управлять портами запуска:

- в `env` pm2 изначально пробрасывается переменная `NITRO_HOST` со значением `'0.0.0.0'`, это нужно для старта сайта до настройки домена и выпуска SSL сертификата
- после настройки nginx нужно изменить значение переменной `NITRO_HOST` на `'127.0.0.1'` чтобы открыть только локальный доступ (nginx сам проксирует запросы к фронтенду на нужный домен)

Все команды выполняются из корня проекта (где нахдится Makefile)

| Команда            | Описание                                                            | Когда использовать                  |
| ------------------ | ------------------------------------------------------------------- | ----------------------------------- |
| `make app-init`    | Первая инициализация (установка зависимостей + сборка + запуск PM2) | При первичном развертывании         |
| `make app-build`   | Установка зависимостей и сборка проекта                             | При необходимости пересборки        |
| `make app-clean`   | Удаление старой сборки (`.output`)                                  | Перед новой сборкой                 |
| `make app-deploy`  | Полный деплой (clean -> build -> reload)                            | **Основная команда** при обновлении |
| `make app-reload`  | Graceful reload PM2 (без downtime)                                  | После деплоя                        |
| `make app-restart` | Жёсткий рестарт PM2                                                 | При критических изменениях          |
| `make app-logs`    | Открыть последний лог в VS Code                                     | Быстрый просмотр логов              |
| `make app-logtail` | Показать последние 100 строк логов в терминале                      | Мониторинг в реальном времени       |

### Работа `pm2`
После старта pm2 (командой `make app-init`) из файла конфигурации `ecosystem.config.js` собраный фронтенд открывается на 3000 порту, активируется демон pm2 и делается первый дамп, то есть при рестарте сервера или какой то ошибки сайт сам перезапускается и сохраненного дампа.

После каждого вызова `make app-deploy` также делается дамп, что исключает необходимости каждый раз вызывать `pm2 save` вручную.

Для логирования стандартная папка pm2 переопределена на `/srv/<название_проекта>/logs`.

### Разница между `reload` и `restart`

- `app-reload` — Graceful reload: PM2 перезапускает приложение без разрыва соединений (рекомендуется для продакшена).
- `app-restart` — Полный останов и запуск заново (используется при серьёзных изменениях в конфигурации или когда reload не помогает).

## Примеры использования

```bash
# Первичная установка
make app-init
```

```bash
# Обычный деплой после изменений
make app-deploy
```

```bash
# Только пересобрать без деплоя
make app-build
```

```bash
# Перезапустить без пересборки
make app-reload
```

```bash
# Посмотреть логи
make app-logs
# или
make app-logtail
```
