# useCms

Composable для получения данных из CMS через nuxt-роут `/api/cms/*` с поддержкой типизации, кэширования и гибкой конфигурации запроса.

Используется как универсальный слой для работы с CMS в приложении:

- получение коллекций
- фильтрация, сортировка и ограничение данных
- управление SSR-кэшированием через `useFetch`

## Функционал

- Построен на основе `useFetch` (Nuxt)
- Поддерживает generics для типизации ответа (`<T>`)
- Автоматически формирует query-параметры
- Генерирует уникальный ключ запроса (`key`) для кэширования
- Поддерживает SSR и повторное использование данных через `payload`
- Инкапсулирует структуру ответа (`{ data: T }`)
- Возвращает уже "распакованный" контент (`content`)

## Параметры

### Основные

| Параметр        | Тип                | Описание                       |
| --------------- | ------------------ | ------------------------------ |
| `collection`    | `string`           | Название коллекции CMS         |
| `withRelations` | `string[]`         | Связанные сущности (relations) |
| `requestOpt`    | `AsyncDataOptions` | Опции `useFetch`               |

### Дополнительные (`opts`)

| Параметр       | Тип        | По умолчанию | Описание                                   |
| -------------- | ---------- | ------------ | ------------------------------------------ |
| `resolveFiles` | `boolean`  | `true`       | Разрешать файлы (CMS-specific) @deprecated |
| `force`        | `boolean`  | —            | (не используется в текущей реализации)     |
| `key`          | `string`   | auto         | Кастомный ключ кэширования                 |
| `cacheTtl`     | `number`   | —            | (не используется)                          |
| `query`        | `CmsQuery` | —            | Дополнительные параметры запроса           |

### CmsQuery

| Поле     | Тип                   | Описание                          |
| -------- | --------------------- | --------------------------------- |
| `fields` | `string \| string[]`  | Выбор полей                       |
| `filter` | `Record<string, any>` | Фильтрация (сериализуется в JSON) |
| `sort`   | `string`              | Сортировка                        |
| `limit`  | `number`              | Ограничение количества            |

## Возвращаемое значение

| Поле      | Тип                      | Описание         |
| --------- | ------------------------ | ---------------- |
| `content` | `ComputedRef<T \| null>` | Данные из CMS    |
| `status`  | `AsyncDataRequestStatus` | Статус запроса   |
| `refresh` | `() => Promise<void>`    | Повторный запрос |

## Поведение

- Формирует query:
    - `relations` → строка через запятую
    - `resolveFiles` → boolean
    - параметры из `CmsQuery`
- Генерирует `key` на основе:
    - коллекции
    - relations
    - query
    - request options
- Использует `getCachedData`:
    - берёт данные из `nuxtApp.payload.data` (SSR-кэш)
- Всегда выполняет запрос (`immediate: true`, `server: true`)
- Возвращает `content` как `data.value.data`

## Особенности кэширования

- Кэшируется на уровне Nuxt через `key`
- Повторные вызовы с одинаковыми параметрами не делают повторный запрос
- Возможна ручная инвалидация через `refresh`

## Пример использования

```ts
const { content, status } = await useCms<Article[]>('articles');

const { content: articles } = await useCms<Article[]>(
	'articles',
	['author.*', 'image.*'],
	{ lazy: true },
	{
		query: {
			sort: '-date',
			limit: 10,
			filter: { published: { _eq: true } },
		},
	},
);
```
